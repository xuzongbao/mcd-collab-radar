# 价梯计算规则

联名周边的购买机制拆解与最优路径计算规范。所有价格必须来自 `calculate-price` 实时计算。

## 一、联名周边的四种官方机制

| 机制 | 说明 | 计算方式 |
|---|---|---|
| **换购** | 任意消费 +N 元得周边（如 +39.9） | 凑单餐品价 + N = 总成本 |
| **加购** | APP/小程序内直接加购周边 | 周边标价（可能有会员价） |
| **随单得** | 购买指定联名套餐赠周边（如小卡） | 套餐价（周边视为 0 成本附加） |
| **积分** | 积分兑换 / 积分抢先购 / 积分抽奖 | 积分价值折算 + 消耗积分数 |

> ⚠️ **已实跑验证的重要认知（2026-10-13）**：麦当劳 × PEACEMINUSONE 的周边（棒球帽/徽章/丝巾）**不在 `mall-points-products` 积分兑换列表中**，实际机制是「任意餐品消费 +39.9 元换购」。
> 因此**优化目标是最小化凑单餐品价格，而不是攒积分**。全菜单中最便宜的"任意消费"是圆筒冰淇淋 ¥5（`calculate-price` 实算 500 分）→ 到手 ¥44.9。
> 每次接到联名需求，都应先用 `mall-points-products` 核实周边究竟是"换购"还是"积分兑换"，不要凭经验假设。

## 二、价梯计算步骤（按序执行）

1. **确定目标周边**及其官方机制（来自 `campaign-calendar` / `mall-product-detail`，并用 `mall-points-products` 交叉核实是否为积分兑换）
2. **找凑单下限**：`query-meals` 中价格最低的可随单餐品（注意联名套餐通常要求指定餐品，先 `query-meal-detail` 确认）
3. **算基础路径**：`calculate-price` 分别算
   - 路径 A：凑单套餐 + 换购价
   - 路径 B：直接加购
4. **叠加会员权益**：
   - 麦金卡：通常随单再减（以实时结果为准）
   - 早餐卡：早餐时段
5. **叠加优惠券**：`query-store-coupons` + `available-coupons` 匹配可用券，重新 `calculate-price`
6. **评估积分路径**：`query-my-account` 看积分余额；`mall-points-products` 看积分兑换选项
7. **输出最优解**：比较各路径实付，标注 ✅

## 三、价梯表输出格式

| 周边 | 官方机制 | 凑单到手价 | 券后价 | 积分路径 | 最优解 |
|---|---|---|---|---|---|
| 联名徽章（一套三枚） | 任意消费 +39.9 | ¥44.9（圆筒冰淇淋 5 + 39.9） | 视券而定 | 10/15 10:40 抢先购 | ✅ ¥44.9 |

规则：
- 每个数字必须可追溯（来自 `calculate-price` 或工具返回）
- 不确定的机制不要假设，先查 `query-meal-detail` / `campaign-calendar`
- 用户没有麦金卡时，不要虚构该优惠
- **区分"最省"与"最值"**：极简凑单总价最低，但用户可能想顺带吃饱——应同时给出饱腹路径（如龙焰鸡腿堡三件套 ¥26.9 → 到手 ¥66.8），让用户自己选

## 四、红线

- **不算投资回报**：不比较"现在买 vs 以后二手价"，不给升值预期
- **不鼓励囤积**：默认建议"按需购买，喜欢再冲"
- **不凑单过度**：若凑单餐品用户不吃，应提示"为了周边点多一份是否值得"，尊重用户选择

## 五、降级

- `calculate-price` 失败：展示各机制标价，注明"精确价格待 MCP 恢复后重算"
- 用户未登录 MCP（无积分数据）：跳过积分路径，仅算现金路径
